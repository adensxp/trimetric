# 部署机升级 Runbook（v5.3.30 旧代码 → v5.3.31 四库架构，约 10 分钟）

> 在部署机（/workspace 环境，mavis CLI 可用）执行。每步有验证点，出错停在该步排查后再继续。
> cron 管理策略：**方案 B（声明式）** —— 仓库 `cron/prompts/` 为唯一事实源，重建即对齐。

## 前置确认

- [ ] `mavis cron list` 有输出（CLI 可用）
- [ ] 本机项目代码为最新（本仓库 main 分支）

## 1. 同步代码

整目录覆盖 `scripts/` + `cron/` + `tests/` 到 `/workspace/stock_db/`。
**必须整目录**：config.py / rules.py / init_db.py / fetch_data.py / migrate_to_4db.py / export_schema.py 均为新增或大改文件。

- 验证：`python3 -m py_compile /workspace/stock_db/scripts/*.py` 无输出

## 2. 数据迁移（一次性）

```bash
cd /workspace/stock_db && python3 scripts/migrate_to_4db.py
```

- 验证：输出 4 个 ✅（master 整库复制 + candidates/positions/capital 按表拆分）
- 老 `stock_data.db` / `portfolio.db` 原样保留（回滚保险）；BSC 两个快照库退役

## 3. cron 重建（方案 B）

```bash
# 3a. 删除全部旧任务（含 9-12 会话直建的 daily-quality-check / pool-rotation）
mavis cron list                     # 记下全部任务名与 task_id
mavis cron delete --help            # 查参数格式后逐个删除

# 3b. 从仓库重建 10 个任务（prompt 全静态）
bash cron/rebuild_cron_tasks.sh

# 3c. 回填新 task_id
mavis cron list                     # 把新 ID 填入 cron/cron_tasks_8.json 的「（部署机回填）」占位
```

- 验证：`mavis cron list` 显示 10 个任务（5×monitor + morning-prep + daily-pool + stock-db-update + daily-quality-check + pool-rotation）

## 4. schema 基线

```bash
python3 scripts/export_schema.py > docs/schema.sql
git add docs/schema.sql && git commit -m "schema 基线（部署机 v5.3.31）" && git push
```

## 5. 总验证

```bash
python3 tests/test_rules.py && python3 tests/test_config.py   # 33 项全绿
python3 scripts/monitor.py                                     # 四库读数正常（持仓/候选/大盘）
```

## 回滚预案

| 层 | 动作 |
|----|------|
| 数据 | 删 4 个新库文件即回旧格局（老库未动） |
| 代码 | `git checkout v5.3.30-rel` |
| cron | 重新 `mavis cron create`（旧 prompt 若未存档，从 mavis 操作日志恢复） |

## 日常升级（此后）

改代码/prompt → git push（CI 绿）→ 部署机 `git pull` → 若 cron prompt 有变：删旧任务 + 重跑 rebuild 脚本。
`mavis cron update` 仅用于临时热修（改调度/禁用），**用完必须回写仓库**。
