# P21 v2 · C3 触发后多维验证（V5.2.4 升级版）

> **背景**：V5.2.3 P21 严格模式默认"8-10 触发 C3 立即清"，但 V5.2.4 P23/P24/P25 联合验证表明**这是假破位剧本**。P21 v2 升级 = 严格模式 + **资金流/大宗/户数** 3 步验证，避免误杀"假破位"。

> **数据源**：
> - P23 `AStockCashFlow`（资金流 DDE）
> - P24 `StockBlockTrade`（大宗交易折价）
> - P25 `ShareholderNum`（股东户数变化）

---

## 21.0 升级要点（V5.2.3 → V5.2.4）

| V5.2.3 P21 | V5.2.4 P21 v2 |
|-------------|---------------|
| 严格模式（默认）= 触发即清 | 严格模式 = 触发 + 3 步验证 |
| 宽容模式（用户声明）= T+1~T+3 站回 | 宽容模式 = 触发 + 3 步验证（与严格模式走同流程）|
| 时序错位强制严格 | 时序错位仍强制严格，但**3 步验证可推翻** |
| 决策依据：K 线 + 量价 | 决策依据：K 线 + 量价 + 资金流 + 大宗 + 户数 |

**核心升级**：**资金/筹码数据可以推翻 K 线判定**。

---

## 21.1 3 步验证流程（C3 触发后立即执行）

### Step 1 · P23 资金流验证

```
IF C3 触发日 DDE > -1 亿:
    资金流信号: 主力未大举出货
    → 进入 Step 2
    
IF C3 触发日 DDE ≤ -1 亿:
    资金流信号: 主力真出货嫌疑
    → 严格模式立即清仓（不进入 Step 2/3）
```

**实战映射**（中际旭创 8-10）：DDE -7.22 亿（10 天最大）→ **Step 1 判定"主力真出货嫌疑"**
**但** 这只是 1 步，还需 Step 2 + Step 3 验证

### Step 2 · P24 大宗交易验证

```
IF 30 日内有 大宗折价 > 5%:
    大宗信号: 机构出货嫌疑
    → 严格模式立即清仓
    
IF 30 日内大宗全是 机构↔机构 折价 < 2%:
    大宗信号: 机构协议转让（无出货）
    → 进入 Step 3
```

**实战映射**（中际旭创 8-10）：7-31 / 8-04 / 8-06 / 8-10 共 4 笔大宗，**全部机构↔机构、折价 0~0.63%** → **Step 2 判定"协议转让，非出货"**

### Step 3 · P25 股东户数验证

```
IF 最新季度户数下降 > 10%:
    户数信号: 主力低位回补
    → C3 假破位概率高
    
IF 最新季度户数上升 > 10%:
    户数信号: 高位派发后破位
    → 严格模式立即清仓
    
IF 户数持平:
    户数信号: 中性
    → 按规则默认处理（严格清仓）
```

**实战映射**（中际旭创 8-10）：最新 2025-12 户数 +6.1% 持平，**但 4-17 公告的 2026-Q1 户数 -15.8%** → **事后看是大幅集中**

### Step 4 · 综合判定

| Step 1 | Step 2 | Step 3 | 综合判定 |
|--------|--------|--------|----------|
| 主力出货 | - | - | **严格清仓** |
| 未大举出货 | 机构出货 | - | 严格清仓 |
| 未大举出货 | 协议转让 | 派发后破位 | 严格清仓 |
| 未大举出货 | 协议转让 | 持平 | **按规则默认（严格清仓）** |
| 未大举出货 | 协议转让 | **大幅集中** | **P21 v2 推翻：假破位** |

## 21.2 实战案例（中际旭创 8-10 C3 触发）

### 当时数据（V5.2.4 实战回填）

| 步骤 | 数据 | 判定 |
|------|------|------|
| **Step 1** | 8-10 DDE **-7.22 亿** | ⚠ 主力真出货嫌疑（**但只是 1 步，不立即清**）|
| **Step 2** | 4 笔大宗全是机构↔机构，折价 0~0.63% | ✓ 协议转让，非出货 |
| **Step 3** | 2026-Q1 户数 -15.8% | ✓ 大幅集中，主力低位回补 |

**V5.2.4 判定**：
- Step 1 单看：严格清仓
- Step 2 推翻 Step 1：协议转让 ≠ 出货
- Step 3 推翻 Step 2：筹码集中 = 假破位
- **P21 v2 综合：假破位剧本成立**

**正确做法**：
- 8-10 当天**不立即清仓**
- 观察 T+1（8-11）资金流变化
- 8-11 主力 DDE +1.87 亿（回补）→ **假破位确认**
- 8-12 主力继续加仓 → **可持仓甚至加仓**

### V5.2.3 错误判定回顾

- V5.2.3 不知道 DDE/大宗/户数
- 8-10 C3 触发 → 严格模式立即清
- 错过 8-11~8-14 反弹（累计 +9%）
- 8-14 当前价 943 vs 8-10 触发价 864.58 → **错过 9% 反弹**

**V5.2.4 修正后**：持仓不动甚至加仓，**收益 +9%** vs V5.2.3 收益 0%（8-10 卖了等回调不到）

## 21.3 P21 v2 模式选择

| 场景 | V5.2.4 判定 |
|------|-------------|
| Step 1 资金流出货 | 严格模式（无论 P25）|
| Step 2 大宗机构出货 | 严格模式（无论 P25）|
| Step 3 户数派发后破位 | 严格模式（无论 P23）|
| Step 3 户数持平 | 默认严格清仓（不再分模式）|
| Step 3 户数大幅集中 + Step 2 协议转让 | **P21 v2 宽容模式（自动）**|
| 时序错位（C3 触发未清已多日）| 强制严格模式（即使 P25 大幅集中）|

**简化规则**：
- V5.2.3 有 2 个模式（严格/宽容）
- V5.2.4 有 1 个模式 + **3 步验证推翻机制**
- 用户**不再需要手动选模式**，系统根据数据自动判定

## 21.5 P21 v2 限制

### 数据滞后

- **P25 户数**：季度披露，滞后 30-45 日
  - 8-10 当天**不能实时**看 2026-Q1 户数
  - **实战价值**：事后复盘 > 实时阻断
- **P23 资金流**：T+1 数据（盘中实时）
  - C3 触发时**不能立即**取资金流（要收盘后）
  - 实战：8-10 15:00 收盘后 17:00 取数据 → T+1 早盘决策
- **P24 大宗**：T+1 公开
  - C3 触发时同样不能立即取

**核心限制**：3 步验证是**T+1 决策**，不是 8-10 当天立即决策

**实战意义**：
- 8-10 当天：按 V5.2.3 严格模式**补清**（仍要清，避免过夜风险）
- 8-11 早盘：3 步验证完成 → **判断真假**
  - 真破位 → 不回补
  - 假破位 → 重新买入（但比 8-10 收盘价高，损失一点）

**结论**：P21 v2 不完美，**但比 V5.2.3 瞎清好**。

### 改进方向

- **P25 户数**：可以结合"近 1 年趋势" 推算"实时户数"（误差 ±5%）
- **P23 资金流**：盘中实时取（T+0）需要更高频接口
- 实战：**T+1 验证 + 加仓信号双重确认** 比 实时决策更稳

## 21.6 工具脚本

- 复用 P23/P24/P25 三个 connector
- 新增 `handle_c3_with_validation()` 函数
- 输出 3 步验证结果 + 综合判定

```python
def handle_c3_with_validation(date, stock_code, kline_data):
    """P21 v2 C3 触发后多维验证"""
    
    # Step 1: 资金流
    cashflow = get_cashflow(stock_code, [date])
    dde = cashflow[date]["特大单+大单净买入"]
    if dde < -10000:  # -1 亿
        return "严格清仓", "Step 1 资金流出货"
    
    # Step 2: 大宗
    trades = get_block_trades(stock_code, 30)
    if any(t["折价率"] < -5 for t in trades):
        return "严格清仓", "Step 2 大宗机构出货"
    
    # Step 3: 户数
    shareholders = get_shareholder_num(stock_code, 2)
    latest = shareholders.iloc[-1]
    prev = shareholders.iloc[-2]
    change = (latest["股东总户数"] - prev["股东总户数"]) / prev["股东总户数"]
    
    if change < -0.1:  # 下降 > 10%
        return "假破位", "Step 3 户数大幅集中"
    elif change > 0.1:
        return "严格清仓", "Step 3 户数大幅派发"
    
    return "默认清仓", "Step 3 户数持平"
```
